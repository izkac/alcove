Stop the desktop flash on Win+D

Alcove change: desktop-zorder-owner

TL;DR

Pressing Win+D makes Alcove blink. The cause is not sloppy timing: Windows raises the desktop over Alcove, and Alcove fights its way back on top, which is the flash you see. This change lets Alcove ride along with the desktop instead of racing it, so there is nothing to fight and nothing to flash.

What you'll get

  • Win+D leaves the desk exactly where it is. No blink, no blank frame, no wallpaper peeking through.
  • Everything else stays as it is: applications still cover the desk, clicking the desk still works, the desk still hides Explorer's icons.
  • Alcove survives an Explorer restart the way it does today, and puts itself back in place within about two seconds.
  • Slightly less background work. A polling loop that ran thirty times a second in bursts is deleted along with the code it existed to serve.

How it works

Windows lets one window declare another as its owner. An owned window is always drawn above its owner. Explorer's desktop icons never blink on Win+D for exactly this reason: they belong to the window Windows raises. Alcove will name that same window as its owner, and inherit the same immunity.

Today Alcove instead watches for the moment it gets covered and then shoves itself back to the front. That shove is the flash. Once ownership is in place, the watching and the shoving are both deleted.

This was measured, not guessed. Test windows were driven through a real Show Desktop on this machine. Alcove is never minimized by Win+D, which is what the current code assumes. It is covered. The ownership approach was then confirmed to hold position through Win+D, to still let ordinary applications cover the desk, and to survive its owner being destroyed.

What changes for you

Nothing to learn and nothing to configure. No new setting, no new command, no change to how drawers or the desk behave. The only difference you should notice is the absence of the flash.

Risks and open questions

RiskWhere it stands
Explorer restarting takes the desk with it Tested and ruled out. When the owner window dies, Windows leaves our window alive and simply forgets the ownership. Alcove re-establishes it on its next sweep.
Alcove floats above applications instead of behind them Tested. A maximized foreground window still covers the desk. Ownership only orders Alcove against the desktop, not against everything.
Windows 11 behaves differently Unverified — this machine is Windows 10. The change reuses the existing desktop-window lookup rather than adding assumptions, so a different layout is found the same way it is today. Worth a check on Windows 11 before release.
Something else minimizes the desk The existing safety net for a minimized or hidden desk is kept, just no longer used for Win+D.

Verification status

Checked end to end on this machine. Pressing Show Desktop with the change running: the desk stays put in all 31 measurements taken across the transition, is never covered by the desktop, and is never minimised. Ordinary windows still cover it afterwards, as before.

Restarting the desktop was tested too. Explorer was killed and restarted while Alcove was running. Alcove survived, noticed that the desktop had come back as a different kind of window, re-attached itself to the new one, and kept the icons hidden. Releasing the desktop with the emergency shortcut also works: the icons come back and Alcove becomes a normal window.

One check remains open: a second monitor, which this machine does not have.

A correction to an earlier version of this brief. It claimed the current code builds an app that never appears. That was my mistake. I had built the test copy with the wrong command, producing a build that looks for a development server instead of using its own built-in interface. Built the normal way, it works. There is no such problem in your code, and the warning has been withdrawn.

Separately, and not caused by this change: this machine currently has the desktop icon list hidden with no Alcove running. That is either a leftover from a run that was killed, which the next start repairs on its own, or the Windows "Show desktop icons" setting being off. It was left untouched.

Out of scope

  • Making Alcove a true child window of the desktop. It was measured and it works, but a child dies when its parent dies, so an Explorer restart would destroy the desk. Ownership does not have that failure.
  • Any change to wallpaper painting, icon hiding, drawers, or search.
  • The unrelated open item on removable-drive drawers.
